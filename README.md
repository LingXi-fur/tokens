## Try it without installing or using your own logs

Open the [interactive synthetic demo](https://lingxi-fur.github.io/tokens/demo/) to explore the dashboard with invented records. It does not refresh from your machine. After cloning, `./run demo --open` generates the same kind of local-only sample report.

## Why use it?

AI coding tools already leave usage records on your machine, but each tool stores and counts them differently. `tokens` gives you one inspectable local view:

- **See usage from Claude Code, Gemini CLI, and Codex** in one report while keeping each source's reported token semantics visible.
- **Find changes worth inspecting:** daily, weekly, and monthly trends, two-period comparisons, and peak periods.
- **Trace recorded contributors:** model, source, project, and session details where the logs provide them.
- **Keep results under your control:** exact tables, CSV and Markdown exports, local live refresh, or a self-contained offline HTML snapshot.

The local CLI and dashboard require no account, telemetry endpoint, hosted backend, or external runtime assets; your AI coding tools and this documentation site have their own network policies. Core parsing, aggregation, reporting, and loopback serving use the Python standard library. Windows additionally needs the data-only `tzdata` package for consistent IANA timezone support.

## Clone and run

Requirements: Python 3.9 or newer on macOS, Linux, or Windows. To analyze your own usage, you also need existing local logs from a supported AI coding CLI; the synthetic demo needs no logs.

```bash
git clone https://github.com/LingXi-fur/tokens.git
cd tokens
./run doctor
./run serve --open
```

Claude is the default source. If you use Gemini CLI or Codex, add `--source gemini` or `--source codex` to `serve`; repeat `--source` to combine sources. Otherwise, their logs will not appear.

`./run doctor` checks paths, candidate file counts, timezone, output, and cache permissions. It does not parse message contents or print project and session identifiers.

The live dashboard binds only to `127.0.0.1`. It checks for local log changes every five minutes by default; the page can switch between 1, 5, 15, or 30 minutes, or pause refresh. Unchanged files are not reparsed or retransmitted.

No local logs yet? Open a full synthetic dashboard generated through the same reporting pipeline:

```bash
./run demo --open
```

The demo writes `out/dashboard-demo.html` from generated sample data only. It does not read Claude Code, Gemini CLI, or Codex logs.

Create an offline archive instead:

```bash
./run dashboard --open
```

### Windows source checkout

Install the checkout in a local virtual environment first. This also installs the required `tzdata` package:

```powershell
git clone https://github.com/LingXi-fur/tokens.git
cd tokens
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
tokens doctor
tokens serve --open
```

If you use Gemini CLI or Codex, add `--source gemini` or `--source codex` to `tokens serve --open`.

### Optional local command install

From the cloned checkout, install an editable command into a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e .
tokens doctor
tokens serve --open
```

This installs from your local checkout. No package-registry release is required by these instructions.

## Choose an output

| Goal | Source-checkout command | Behavior |
|---|---|---|
| Quick terminal summary | `./run day` | Last 14 days in the terminal |
| Try before installing | [Open the hosted synthetic Demo](https://lingxi-fur.github.io/tokens/demo/) | No clone, account, local logs, or upload |
| Explore locally without logs | `./run demo --open` | Synthetic data only; writes `dashboard-demo.html` |
| Keep a dashboard open | `./run serve --open` | Loopback-only service with in-page updates |
| Save an offline archive | `./run dashboard --open` | Self-contained generation-time snapshot |
| Prepare a safer sharing copy | `./run dashboard --anonymize --open` | Pseudonymizes selected identifiers |

Reports are written to `./out` by default. Use `--output DIR` to choose another location.

## What can you learn?

Find your busiest days, compare two equal-length periods, and see which **recorded** models, projects, or sessions contributed to the difference. When source records provide the fields, you can:

- **Spot changes:** explore daily, weekly, and monthly trends, peak periods, and token composition.
- **Follow the records:** filter by source and model, inspect project and session aggregates, and see original model names grouped under Other in a non-anonymized dashboard.
- **Check the numbers:** switch from charts to exact tables, export CSV or Markdown, or save a self-contained offline HTML snapshot.

The interactive [Dashboard guide](https://lingxi-fur.github.io/tokens/dashboard.html) covers the A/B interval lens, peak profile, keyboard controls, achievements, and other views. A/B compares recorded token contributions; it does not establish why usage changed. A zero baseline reports absolute Token change only. Projects and sessions are parallel aggregates, not automatically paired. Selected A/B periods and an open peak profile may be restored from the URL; project/session IDs and exact token details are not written there.

Token change describes usage, not productivity or code quality. Cache Read is cached-token volume, not guaranteed monetary savings.

## Supported sources

| Source | Default local path | Project data | Session data | Accounting note |
|---|---|---:|---:|---|
| Claude Code | `~/.claude/projects/**/*.jsonl` | Yes | Yes | Total is input + output + cache read + cache write. |
| Gemini CLI | `~/.gemini/tmp/*/chats/session-*.json` | Usually no | Yes | Uses source `tokens.total` when available. |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` | Usually no | Usually no | Cached input is already included in input and is not added twice. |

Claude is the default source. Repeat `--source` to combine tools:

```bash
./run serve \
  --source claude \
  --source gemini \
  --source codex \
  --open
```

Different tools do not expose identical token semantics. `tokens` preserves each source's reported total instead of pretending the values are perfectly interchangeable.

## CLI essentials

```text
./run [day|week|month|all|dashboard|demo|serve|doctor] [options]
tokens [day|week|month|all|dashboard|demo|serve|doctor] [options]  # after local install
```

| Option | Purpose |
|---|---|
| `--source claude\|gemini\|codex` | Select a source; repeat to combine sources. |
| `--since YYYY-MM-DD` / `--until YYYY-MM-DD` | Limit the inclusive report range. |
| `--timezone AREA/CITY` | Override the detected system timezone. |
| `--lang en\|zh` | Terminal and static HTML language; default follows system locale (`TOKENS_LANG` overrides it). |
| `--output DIR` | Choose the report directory; default is `./out`. |
| `--html` | Add a static HTML report to terminal modes. |
| `--anonymize` | Pseudonymize identifiers in dashboard or live mode. |
| `--interval SECONDS` | Set initial live check interval; minimum 1, default 300. |
| `--port PORT` | Set loopback port; default 8765, or 0 for an available port. |
| `--open` | Open generated file or local URL in the default browser. |
| `--no-cache` | Re-read all selected log files. |

See the [complete CLI reference](https://lingxi-fur.github.io/tokens/cli.html).

## Privacy

`tokens` reads local files and performs analysis locally. Offline snapshots make no network requests. Live mode talks only to its same-origin service on `127.0.0.1` and provides no LAN binding option. When present, `~/.claude-code-router/custom-router.js` is read locally as text only; it is never executed or uploaded. Router rules are used only to interpret plain Claude request aliases and never rewrite Gemini or Codex model names.

A normal dashboard may still contain:

- project paths and working directories
- session identifiers and locally derived titles
- exact dates, models, token values, and per-turn token sequences
- behavioral patterns that could identify a person or organization

`--anonymize` replaces project paths, session identifiers, and natural-language titles with report-scoped aliases. Exact dates, retained model names, token values, relationships, and replay sequences remain. Non-anonymized dashboards additionally show original names and exact usage for models folded into the chart’s Other color slot; anonymized exports omit these overflow names. Router-resolved backend names can reveal local routing configuration. This is **pseudonymization, not guaranteed anonymity**.

Before sharing a report:

1. use `./run dashboard --anonymize` and confirm the file is `dashboard-anonymized.html`, not an older regular `dashboard.html`
2. restrict the date range
3. inspect the generated file, including embedded data, and any screenshot, export, or view URL you share
4. search for usernames, customer names, repository names, and custom model labels
5. never attach raw logs to a public issue

Read the full [data and privacy guide](https://lingxi-fur.github.io/tokens/data-and-privacy.html).

## Current boundaries

- Public setup currently starts from a source checkout; registry install commands are intentionally not advertised until a verified release exists.
- Claude is the only default source. Gemini and Codex must be selected explicitly.
- Source formats expose different fields, so some project, session, or context views can be unavailable.
- Terminal and static reports support English and Chinese via `--lang en|zh`, defaulting to your system locale; the interactive dashboard has its own in-page language switch.
- An offline dashboard is a generation-time snapshot. Use `./run serve --open` for ongoing updates.

## Troubleshooting

**No logs found?** Run `./run doctor`. If Claude is not your tool, try `./run day --source gemini` or `./run day --source codex`. To explore without any local logs, run `./run demo --open`; an installed checkout can use `tokens demo --open`.

**Dashboard numbers do not change?** `./run dashboard` creates an offline snapshot. Use `./run serve --open` for live updates.

**Browser did not open?** Command still prints generated path or local URL. Open it manually.

More answers are in the [FAQ](https://lingxi-fur.github.io/tokens/faq.html).

## Contributing and security

Bug reports and focused pull requests are welcome. Start with [CONTRIBUTING.md](https://github.com/LingXi-fur/tokens/blob/main/CONTRIBUTING.md), and use synthetic records when reproducing a problem.

For vulnerabilities or privacy issues, follow [SECURITY.md](https://github.com/LingXi-fur/tokens/blob/main/SECURITY.md) rather than opening a public issue. Never include raw logs or an unreviewed generated dashboard.

If `tokens` helps, a star makes it easier for other local-first AI tool users to find. Real platform feedback and bug reports matter even more.
