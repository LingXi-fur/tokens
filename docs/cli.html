COMMAND-LINE REFERENCE

One command, local reports

Use ./run from a source checkout, or tokens after a local editable install or release wheel install.

Syntax

./run [day|week|month|all|dashboard|demo|serve|doctor|quota|outcomes] [options]  # source checkout
tokens [day|week|month|all|dashboard|demo|serve|doctor|quota|outcomes] [options]  # local editable install or wheel

Subscription quota (quota)

tokens quota reports remaining subscription capacity and projected limit times. Use --json for machine-readable output, --source to limit sections, and --no-cache to bypass the local quota-v1.json scan cache.

  • Codex vs. Claude: Codex reads official rate_limits snapshots from local session logs (distinguishing 5-hour and weekly windows by window_minutes, showing real used percentages, reset times, and recent burn rate; expired windows are marked instead of showing stale percentages). Claude exposes no official percentage, so its section is an explicit estimate built from Anthropic-direct tokens inside 429 rate-limit windows (hits) or the highest completed window without a hit (safe_floor); CCR-routed backends are excluded. OpenCode reports that no official quota data exists.
  • Five projection statuses: hit (projected to reach the limit before reset, or already hit), safe (projected limit is after reset; safe this window), past_floor (projected to pass the highest no-limit safe_floor, which is not a predicted limit hit), beyond_estimate (current usage already exceeds the historical estimate without a hit, meaning the estimate is low), and insufficient (window just started or fewer than two snapshots / too short a span to estimate velocity).
  • First-run speed: The initial run scans all local logs (which may take a few minutes); subsequent runs reuse quota-v1.json and the reader cache and finish in seconds.
  • Privacy: Only rate-limit metadata fields, timestamps, model names, and token totals are read locally—no network requests, no message text, and no cwd, session IDs, or project names in output.

Token outcomes (outcomes)

While quota asks “how much is left?”, tokens outcomes asks “what did the spend produce?” It matches each session's working directory to its local git repository (worktrees of the same repository roll up into the main repository; deleted OpenCode worktrees and Gemini sessions registered in ~/.gemini/projects.json can still resolve), attributes your own non-merge commits (matched via git config user.email / user.name plus comma-separated TOKENS_OUTCOME_EMAILS) from session start until 30 minutes after the session's last activity, and prices sessions using the same official USD reference rates as the Cost Ledger.

  • Retained lines per $1: Surviving lines divided by session spend. A surviving line is an added line still present at HEAD at least 7 days after the commit, measured with read-only git blame and cached per repository and commit in outcomes-blame-v1.json (invalidated when HEAD moves). The summary reports both the all-range ratio (Retained lines per $1) and the settled-only ratio (Retained lines per $1 (settled only), dividing by settled spend). Records without an official reference price contribute tokens but no dollar amount.
  • 7-day observation window (pending lines): Commits younger than 7 days are still in the observation period—their added lines are counted as Pending, while survival stays unknown (—) instead of being reported as zero. If every commit in range is under 7 days old, the terminal prints — (all lines under 7 days old).
  • Rework tax: For settled sessions (commits at least 7 days old), the share of added lines removed within 7 days multiplied by that session's spend (cost × max(0, settled_added − surviving) / added).
  • Cost per commit: Total session spend divided by total attributed and manual commits in the range. Sessions outside any git repository (including missing working directories) and in-repo sessions with zero commits are listed separately; lock files, package-lock.json, dist/, node_modules/, and *.min.js are excluded (extend with semicolon-separated TOKENS_OUTCOME_EXCLUDE).
  • By model and By tool tables & low-sample *: Both tables keep spend exact per (tool, model) bucket without assigning a multi-model session to one “primary model”. Commits, added lines, settled surviving lines, pending lines, and rework tax are allocated by that item's share of the session's priced spend (falling back to token share only when priced spend in the session is zero); one session can appear in several rows, and manual commits outside every session are excluded from both tables. Rows with fewer than 3 sessions or under $1 of settled spend are marked with * as low sample, placed after the ranked rows, and excluded from ranking by Kept / $1.
  • Range, status, and --json: Use --since / --until (inclusive, in the reporting timezone; a lone --since extends to today, a lone --until starts at the earliest record day, and no explicit bound uses the records' own day span), --source, --lang en|zh, and --no-cache. Status is ok, partial (repo_unavailable, 10-second per-file blame_timeout, or the 400-commit per-build blame_skipped budget), or unavailable (git_missing; session spend is still reported). Pass --json for machine-readable output containing schema, range, status, reasons, totals, days, projects, models, sources, no_commit_sessions, and no_repo_sessions.

--openOpen generated HTML or the live local URL in the default browser.
--no-cacheIgnore the user file cache and parse selected logs again.

Behavior and paths

  • Without --source (auto), tokens checks registered source directories and enables every readable source across Claude Code, Gemini CLI, Codex, OpenCode, and Antigravity, reporting detected and skipped sources (doctor includes a "Source discovery" section; doctor --models --json and quota --json include sources_detected and sources_skipped).
  • Reports default to ./out, not the installed package directory.
  • The parsed-file cache (records-v8.json), quota scan cache (quota-v1.json), outcomes blame cache (outcomes-blame-v1.json), and live snapshot cache (live-snapshot/last.json) live in the platform user cache directory, separate from reports.
  • Dates are interpreted in the detected system timezone unless --timezone is supplied.
  • An invalid date, timezone, range, or non-positive window exits with status 2.
  • No records exits with status 1 and points to tokens doctor (in dashboard mode, if files were skipped on Gemini, OpenCode, or Antigravity, a dashboard is still generated so Data Health can explain what was omitted).
  • The live server binds only to 127.0.0.1, accepts no LAN bind option, and can stay open while waiting for future records.
  • The homepage and API serve the most recent successful in-memory snapshot directly; they never wait for the next scan. Initial preparation shows no placeholder zero, and a later scan failure keeps the last good statistics while showing the last successful check time.
  • Background scans compare safe file modification-time and size signatures (plus Windows handle change times); unchanged files are not re-parsed. Conditional requests return 304 only when the published response version is unchanged and there is no scan error; a successful check can advance that version without changing the statistical snapshot.
  • --no-cache disables parsed-file reuse when a live change is detected; it does not turn unchanged polling into repeated full parsing.
  • A browser-open failure does not stop the live server or delete a generated report.
  • --anonymize is pseudonymization, not guaranteed anonymity.
