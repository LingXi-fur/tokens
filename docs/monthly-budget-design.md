# 月度预算与费用节奏——设计规格（Design Spec, No Code This Round）

状态：**仅设计规格**。本轮不实现任何预算代码、不新增预算存储键、不改 `dashboard.js` / `template.html` / `dashboard.css`。实现需另行批准。本文是唯一交付物，冲突时以用户当次授权为准。

命名说明：`docs/` 站点为 HTML，本文件沿用仓库小写连字符命名；不进入站点构建。

## 1. 目标与非目标

功能回答三个问题，嵌入现有**费用账本**卡片，不新建总览 KPI、不造第二个仪表盘：

1. 这个月（按数据时区的自然月）**已估算**多少？
2. 离设定的预算**还差多少**？
3. 按最近节奏，月底**可能**到多少？

非目标：

- 不是实际账单、不是渠道扣费余额、不是 AI 预测或保证值。
- 不做 OS 通知、邮件、webhook 或任何外部服务。
- 不自动换汇、不跨币种合并。
- 不改 Token 统计口径、readers、payload/cache schema。

## 2. 口径与范围

- **自然月**由 payload 的 `timezone`（数据时区）与快照 `generated` 时间决定：`generated` 在数据时区下的 YYYY-MM 即当前预算月。日历只用该时区的 `YYYY-MM-DD` 纯日期运算，不使用浏览器本地时区推月份。
- **闰年与 DST**：月内天数、月末日期由纯日期算法得出（闰年 2 月 29 天；时区换算只在 payload→日期投影时发生一次，之后不依赖时钟偏移），预算计算不再做任何时刻运算。
- **范围独立于趋势筛选**：预算计算不受 A/B 趋势选择、日期选卡、模型按钮筛选影响；范围是**当前载入的全部模型**（含被折叠进 Other 的模型），与费用账本的全量 entries 一致，不复用筛选后的 `costView` 结果。
- **历史静态快照**（离线 HTML）：展示快照**生成月份**与「数据截至 generated 时刻」，明确标注为静态、非实时；**不得**把「最近活动日」（last activity）当作数据截至日。实时页面跟随最近成功快照的 generated。
- **仅基于载入记录**：任何数值都只是「基于载入记录的估算」，载入记录不能证明采集完整；缺行只说明「无载入记录」，**不是**「确认为零」。

## 3. 预算配置（浏览器本地）

- 预算按 **币种 + 自然月** 维度分别设置（USD 与 CNY 各自独立、互不换算、互不换汇）；切换币种不搬预算。
- 预算输入为**严格正十进制字符串**：仅 `0-9` 与一个小数点，可选至多 2 位小数（与金额展示精度一致），不允许符号、空白、千分位、科学计数法；`0`、负数、前导 `+`、空串均非法。
- 独立上限建议 **1,000,000 currency units**（10^6）：超过即拒绝并提示，不给「接近上限」的静默截断。这是防误输入上限，不是用户预算建议。该上限与每百万 Token 单价校验**相互独立**，不复用 `tk-cost-v1` 的校验逻辑。
- **无默认预算**：不设置就不显示余量与占比，只显示已定价小计与限制说明；不提供「推荐预算」。
- **无自动保存**：编辑框输入不落盘，只有显式保存按钮才写存储；**加载阶段绝不写盘**（打开页面不触发保存）。
- 存储拟定新键 `tk-budget-v1`（版本化 JSON），**本轮不创建**；实现时与 `tk-cost-v1` 分键，不合并。
- **损坏不覆写**：读取到无法解析、超上限、非正或结构不符的存储时，忽略其值并在界面说明「存储中的预算配置不可用」，不删除、不重写该存储；本次会话内可重新保存（保存是用户显式动作，此时才覆写）。存储不可用时预算仅本次页面有效。
- 实时页面与离线文件的浏览器存储作用域可能不同，沿用费用账本同类说明。

## 4. 数据可用性与降级（状态优先）

以下任一情况出现时，**只显示已定价小计与限制说明**，不显示确定的预算余量，也不给预测：

- 存在 partial pricing（待定价分量）或 uncertain 覆盖；
- 存在 invalid rows（非法行）；
- `totalIncomplete`（Token 覆盖不完整）；
- 报告范围截断（当前自然月不在载入范围内，或起止被 `--since/--until` 截断）；
- 载入记录不足（见第 6 节样本要求）。

状态清单（同时用于 UI 与验收）：

1. **未设置预算**：显示本月已定价小计；提示可设置预算。
2. **低于阈值**（<80%）：正常展示。
3. **达到 80%**：警示。
4. **达到或超过 100%（>=100%）**：超支。
5. **定价不完整 / 范围截断 / 样本不足**：只给已定价小计与限制，不给余量与预测。
6. **无载入记录**：明确「本月无载入记录」，不称「确认为零」。

状态是 UI 第一优先级：状态不满足时，余量、占比、预测一律不渲染。

## 5. 金额算法

- 复用费用账本的**定标整数（BigInt）**管线：单价×Token 以 10^12 定标计算，输出精确十进制（最多 12 位小数、去尾零）；预算与余量也用同一十进制精确表示，不经过 `Number`，不用展示层两位舍入参与运算。
- 「已估算多少」= 当前自然月内、截至 `generated` 的**已定价小计**（与费用账本口径一致：参考价或手填有效价，未知不计入且不假设为零）。
- 「预算余量」= 预算 − 已定价小计。**载入估算的预算占比不是实际余额保证**：文案必须说明这是「基于载入记录的估算占预算比例」，不是渠道实际扣费或真实账单余额。

## 6. 节奏情景（月末情景估算）

只做一个**可解释的月末情景估算**，不叫预测模型、不是上下界、不是真实账单。变量与公式统一如下：

- **闭合日**：日期 `< generated` 的自然日（generated 当日未闭合，不进任何累计基线）。
- **窗口**：最近**至多 7 个**闭合自然日；**至少 3 个**才输出情景，否则进入「样本不足」状态。
- **变量定义**：
  - `closedSubtotal` = 本自然月内**截至昨日（含）**的累计已定价小计（基线）。
  - `windowSum` = 窗口内闭合日已定价小计之和；`windowDayCount` = 窗口覆盖的**自然日数**（日历天数，含无载入记录的日子；缺行只是「无载入贡献」，**不是确证零**；活动日均值不得冒充自然日均值）。
  - `futureDays` = 从 generated 当日到月末的自然日数，**包含 generated 当日恰好一次**（今日尚未闭合，`closedSubtotal` 不含它）。
- **公式**：
  - `scenarioFuture = windowSum × futureDays ÷ windowDayCount`。内部用精确有理数（BigInt 定标比值）运算，只在展示时舍入。
  - `scenarioMonthEnd = closedSubtotal + scenarioFuture`。这是**完整月末情景估算**（已闭合累计 + 剩余自然日外推），**不是 future-only 值**，UI 标签必须体现「月末情景」而非「剩余将花费」。
  - `todayLoaded` = generated 当日已载入的已定价金额：**仅单独参考展示**，不并入 `closedSubtotal`，也**不得**加到 `scenarioMonthEnd`（剩余自然日外推已覆盖今日），杜绝重复计入。
- **月内中途开始/截断**：若载入报告的 `range.since` / `range.until` 截断本月月初至 generated 前一天所需范围，按「范围截断」处理（第 4 节），不输出情景。最近 7 日窗口本身不必从月初开始；范围涵盖所需日期也不代表完整采集。
- 文案禁止：`≤`/`≥` 式上下界话术、「保证」「至少/至多」、以及「完整采集」；统一表述为「按最近 N 个闭合日节奏的月末情景估算（已闭合累计 + 外推），非保证」。

## 7. 界面（文字 wireframe）

状态优先、色彩之外必须有文字与符号、桌面/移动同构。**同一屏不得同时出现 unknown/定价不完整警告与确定的余量或预测**：一旦降级警告在渲染，余量、占比与情景值必须缺席，反之亦然。

桌面（费用账本卡内一行式摘要）：

```
[费用账本] …existing…
┌ 月度预算（USD · 2026-10，数据时区 Asia/Shanghai） ────────────────┐
│ 状态: ● 已达预算 80%（⚠ 警示）                                     │
│ 已估算(已定价小计): 412.07 USD    今日已估算: 18.20 USD            │
│ 预算: 500.00 USD   余量: 87.93 USD（已用占预算 82.4%，仅载入估算）  │
│ 月末情景: 已闭合累计+按最近 7 闭合日外推 ≈ 551.3 USD（非保证）      │
│ [设置预算] [清除]   说明: 基于载入记录；不含未定价与订阅等非计价项   │
└──────────────────────────────────────────────────────────────────┘
```

降级态（定价不完整）示例：

```
│ 状态: ◐ 定价不完整                                                │
│ 已定价小计: 120.50 USD；存在待定价/uncertain 分量，不显示余量与情景 │
```

未设置态：

```
│ 状态: ○ 未设置预算   已定价小计: 120.50 USD   [设置预算]            │
```

移动（窄屏堆叠，每行一项，状态在最上）：

```
月度预算（USD · 2026-10）
状态: ⚠ 已达预算 80%
已估算: 412.07 USD
今日: 18.20 USD
预算: 500.00 USD
余量: 87.93 USD（已用占 82.4%，仅载入估算）
月末情景: ≈551.3 USD（已闭合累计+外推，非保证）
[设置预算] [清除]
```

可访问性要求：

- 状态同时用**文字 + 符号 + 颜色**表达（`● ⚠ ◐ ○` 等符号与文字标签并存），不单靠颜色；色觉障碍下语义完整。
- 预算编辑控件复用 `template.html` 既有控件样式；键盘可达（Tab/Enter/Esc），Esc 取消不落盘，焦点管理沿用费用编辑器模式。
- 中英双语；金额格式与费用账本一致。
- 不更换既有图表配色，不引入新图表。

## 8. 隐私边界

- 预算只存浏览器本地（拟 `tk-budget-v1`，本轮不创建）；无供应商调用、无 API 密钥、无外部服务、无 OS/浏览器外通知。
- 预算值不嵌入导出报告（CSV/Markdown/SVG/离线 HTML 快照均不含）；离线 HTML 若实现预算显示，仅显示该快照月份的静态估算与「未设置/已设置」状态，不含预算值时明确说明。
- 与 `tk-cost-v1` 同等对待：存储失败时仅当前页面可用。

## 9. 与现有 Token 预测的区别

- Token 侧（如趋势/环比）回答**用量**变化；本功能回答**已定价成本**相对**用户设定预算**的位置，且：
- 预算口径是参考价/手填有效价的**估算**，不是账单；
- 预测是单一可解释节奏情景（自然日均值外推），不与 Token 侧的任何模型/算法共享代码或口径；
- 计算独立于趋势筛选与展示选卡，全模型全月参与。
