# tokens 0.3.0 Release Notes

`tokens 0.3.0` expands local-first AI coding token analytics from three tools to five auto-discovered sources — Claude Code, Gemini CLI, Codex, OpenCode, and Antigravity — while keeping all parsing and reporting strictly on your machine. The interactive dashboard receives a dark-first visual redesign with a Today HUD, same-time pace and model-share insights, an official-reference Cost Ledger with local monthly budgets, itemized `Other` models, and a complete English/Chinese interface. Under the hood, cold scans are roughly 4× faster, cache writes are roughly 5× faster, `tokens quota`, `tokens doctor --models`, and `tokens outcomes` bring rate-limit, routing, and spend-outcome transparency, and cross-platform stability is verified across Windows, macOS, Linux, Chromium, Firefox, and WebKit.

## New Data Sources (Antigravity and more)

- **Antigravity as a fifth local source:** automatically discovers `~/.gemini/antigravity/conversations/` (or `TOKENS_ANTIGRAVITY_DIR`) and reads only SQLite usage metadata (input, output, cache read, model, timestamp, and session) in read-only mode without opening conversation content or summaries.
- **OpenCode as a fourth local source:** reads `~/.local/share/opencode/opencode.db` (honoring `XDG_DATA_HOME`) in read-only SQLite mode, projecting only token, model, timestamp, session, and directory fields (total = input + output + reasoning + cache read + cache write, with reasoning tracked as `thoughts`) and tracking `-wal` updates automatically.
- **Automatic source discovery (`--source auto`):** running `tokens` without `--source` now checks directory and file readability for all five registered sources and enables every available tool without opening log contents, while reporting detected and skipped sources in terminal output, `tokens doctor`, `tokens quota`, and the dashboard header.
- **Model attribution diagnostics (`tokens doctor --models`):** groups Claude and OpenCode usage by logged request name and resolved backend model (with `--since`, `--until`, and `--json`), showing record counts, token totals, date bounds, attribution basis (`logged`, `hex_alias`, `native_direct`, `router_rule`, `opencode_logged`), active CCR router rules, and read-only OpenCode database health counts without exposing project paths or session IDs.

## Token Outcomes

- **`tokens outcomes [--since] [--until] [--json]` reports what the spend produced:** maps each session's working directory to its git repository (worktrees of one repository roll up into it) and attributes your own commits — git config identity, extended by `TOKENS_OUTCOME_EMAILS` — to the session they fall in (from session start to 30 minutes after its last activity); merge commits are excluded, commits outside every session count as manual work, and a lone `--since` runs through today.
- **Survival and rework metrics by day, project, and model:** added/deleted lines, lines still present at HEAD 7 days later (read-only `git blame`, cached per repository and commit and invalidated when HEAD moves), a rework tax (the share of a session's added lines removed within 7 days, times its spend), retained lines per $1 with a settled-only variant, and cost per commit; commits younger than 7 days stay pending (added lines counted, survival unknown rather than zero), and amounts use the official USD reference prices, covering only the priced part.
- **Honest degradation and separate categories:** sessions outside any git repository (with their spend) and sessions without commits are listed separately; the block reports `ok`, `partial` (an unreadable repository, a blame timeout, or the per-build blame budget of 400 commits exceeded — `reasons` names the failed check, alongside `bad_session_ts`, `blame_cache_reset`, `no_repo`, `binary_commit`, and `unestimated_cost`), or `unavailable` when git is missing (session spend still reported).
- **Value by model and by tool:** `tokens outcomes` and a collapsed dashboard “Model comparison” block split spend exactly per (tool, model) and share out commits, retained lines and rework tax by each model's share of spend inside a session, so multi-model sessions no longer credit one “primary model”; rows with fewer than 3 sessions or under $1 settled spend are marked low sample and never ranked. Sessions whose OpenCode worktree was deleted, or Gemini sessions without a recorded directory, are mapped back to their repository from local project records.
- **Same privacy guarantees:** the outcomes block holds only counts, ratios, and labels — no commit messages, file names, or author emails — and project names follow `--anonymize`; lock files, `dist/`, `node_modules/`, and `*.min.js` are excluded from the measurements.

## Dashboard New Features

- **Daily briefing:** the first screen opens with one rule-based sentence (no model calls) on what today's spend produced, four cards (retained lines per $1, rework tax, subscription payback, cache hit rate) and short prescriptions.
- **Dark-first theme and Today HUD:** defaults to a dark canvas with a warm soft-light theme option, translucent shell bars, and a collapsible, draggable Today HUD that displays today's tokens, calls, leading model, and same-time change versus yesterday.
- **Quota burn-down in the Today HUD:** the HUD shows the same forecast as `tokens quota` — one row per Codex (official) and Claude (estimate) window with used percentage, reset time and projected run-out — refreshed by `tokens serve`; a run-out before the reset is highlighted.
- **Overview insights:** adds a Today-vs-Yesterday pace race aligned to the generation clock time (with a 7-day same-time average and full-day projection), a 7-day smoothed model share stream (Share and Stream views), and a multi-week activity calendar.
- **Cost Ledger and Monthly Budget:** ships with built-in official USD reference prices (verified against Google Gemini, OpenAI, Anthropic, DeepSeek, Z.ai, and Moonshot pricing pages; GLM and Gemini rechecked against the official pages on 2026-11-19 — GLM-5.3, 5.3-Flash, 5.3-FlashX, 5.2, 5.1, and 5 use Z.ai's international USD rates including the `zhipu/` names found in logs, cache writes stay at 0 while cache storage is limited-time free, and Gemini 4 Neon, 4 Hydrogen, 2.5 Pro, 2.5 Flash, and 3 Flash Preview use Google's Standard paid tier, with models the pages do not list staying unpriced), per-source/model manual price overrides, single-model reference restore, local monthly budget tracking with closed-day extrapolation, and exact-decimal Cost CSV export.
- **Itemized `Other` and eight model color slots:** reserves neutral gray for `Other`, expands named palette capacity to eight models (guaranteeing at least one color slot per active source with usage), and itemizes every folded model with its source and exact tokens across legends, donut slices, trend tooltips, expandable period-table columns (`Other (N)`), exports, and a "More models" filter.
- **Reporting-timezone date scopes and daily model browser:** filters core views by All report, Today, Yesterday, Last 7 days, or a Specific day in the reporting timezone, paired with a 7-day date strip, on-demand month calendar picker, daily model usage table, request-to-backend Route Map SVG diagram, and daily model CSV export.
- **Equal-length A/B comparison, peak profiles, and view summary copy:** compares two consecutive equal-length periods with recorded project evidence panels, highlights leading-model changes with a `Top model changed X → Y` badge, inspects peak-period breakdowns, and copies a readable text summary of the active view in one click.
- **Redesigned Token destinations:** pairs a project and model overview with paginated session cards (12 per page), an accessible full-session table, per-session turn replay on every row, and scoped SVG export.

## English Interface

- **CLI and in-page language control:** `--lang en|zh` sets the language for terminal tables and static HTML reports (defaulting to system locale or `TOKENS_LANG`), while the interactive dashboard provides an instant `#lang-btn` toggle and exports Markdown in the active dashboard language.
- **Single-pass full re-rendering on language switch:** toggling between Chinese and English immediately re-renders the date-range bar, Today's pace, trend peaks and milestone tooltips, model share stream, SVG labels, already-rendered lazy sections, open dialogs, and live-mode views without requiring a page reload.
- **Unified English number units and date inputs:** English views format large numbers with `K`/`M`/`B` and English month and granularity labels everywhere (never leaking `万`/`亿`), and use a `YYYY-MM-DD` date input with a calendar button so browser locale placeholders never appear in English mode.
- **Complete provenance and badge translation with user-data protection:** translates Data Health freshness sentences, partial/unavailable capability badges (`◐`/`○`), season titles, and work-mode copy on both direct English loads and language switches, while preserving user data (project paths, session titles, prompts, and model names) verbatim.

## Performance

- **~4× faster cold Claude log scans:** prefilters JSONL lines without a `"usage"` key before decoding and parses typical usage lines (≤ 256 KB) with the C JSON decoder while retaining the bounded streaming parser for multi-megabyte lines.
- **~5× faster local cache writes:** encodes each top-level cache entry with the C JSON encoder and streams it to disk within bounded single-entry memory, reducing write time on a 117 MB, 202k-record cache from roughly 3.5 seconds to 0.64 seconds.
- **Non-blocking live service (`tokens serve`):** runs log collection in a single background worker (default every 5 minutes) while browsers poll a lightweight `/api/status` endpoint and download `/api/snapshot` only when data changes, with optional local snapshot persistence (`live-snapshot/last.json`) for immediate display after restart while revalidating.
- **Higher collection ceilings for large local histories:** raises total retained data to 1 GiB, total records to 1,000,000, and the record-cache ceiling to 512 MiB, while reading Claude JSONL files over 64 MiB and physical lines over 4 MiB safely within bounded memory.

## Correctness Fixes

- **Subscription rate-limit tracking (`tokens quota`):** reports official Codex `rate_limits` windows distinguished by `window_minutes` (5-hour and weekly) with reset time, recent burn rate, and projected hit time, alongside explicit Claude 5-hour capacity estimates that exclude CCR-routed third-party backends.
- **Accurate Claude direct vs. CCR router attribution:** keeps the logged Claude model on records carrying native Anthropic request and message evidence (`native_direct`) instead of retroactively rewriting them with current CCR router rules, while deterministically decoding CCR hex aliases (`anthropic/claude-ccr-h…`) to their target backend identity.
- **Strict non-finite token rejection across all sources:** rejects `NaN`, `Infinity`, negative, fractional, and boolean token counts across Claude, Codex, Gemini, OpenCode, and Antigravity by zeroing the record's tokens and marking its billing uncertain rather than polluting totals or dropping the record silently.
- **Visible and retryable skipped files:** when a Gemini, OpenCode, or Antigravity file cannot be read or parsed, Data Health displays the skipped file count and reason per source and retries the file on the next run instead of caching the failure or reporting that no logs exist; incomplete Claude or Codex reads continue to abort safely without overwriting valid caches.
- **Corrupt, partial and empty files told apart:** Data Health separates files that cannot be parsed at all from files where only some records failed (showing how many records were ignored), and an empty file is no longer reported as a failure.
- **Consistent period-over-period and timezone attribution:** uses the full previous period for model delta attribution and dominant-model shift when a date range covers a whole current period, and binds cached record dates to the reporting timezone so timezone changes automatically trigger a clean re-parse.
- **Hardened CSV escaping:** applies shared CSV cell escaping across trend, daily model, and cost ledger exports, protecting delimiters, quotes, line breaks, and spreadsheet formula prefixes (`=`, `+`, `-`, `@`, including after leading whitespace or control characters).
- **Readable day-over-day percentages:** when yesterday at the same time is zero or below 1% of today, the HUD, pace card, trend cards and copied summary say so instead of showing values like +99203.6%; changes above +999% are shown as a multiple.

## Cross-Platform (Windows / Firefox)

- **Windows Python 3.12+ safe-read stability:** resolves false `Collection incomplete (file_changed)` errors on unchanged log files on Windows by comparing creation (`birth`) timestamps across `stat`/`lstat` and `fstat` where supported, while preserving full `ctime` checks on macOS and Linux.
- **Windows same-size rewrite detection:** a log rewritten in place with the same size and a restored modification time is detected on Windows through the handle's change time (`FILE_BASIC_INFO.ChangeTime`).
- **Windows Codex `.jsonl.zst` streaming decompression:** streams compressed Codex archives through a dedicated writer thread on Windows without relying on POSIX-only pipe non-blocking flags or socket-only `selectors`.
- **Windows cache permissions and timezone support:** guards descriptor permission setup when `os.fchmod` is unavailable and declares `tzdata` on Windows so IANA `--timezone` resolution works consistently across platforms.
- **Firefox dashboard navigation and cross-browser parity:** renders the Cost Ledger on initial load and pre-renders preceding lazy cards before section jumps so scrolling or jumping from the section dock or delta attribution never shifts layout mid-scroll, with automated dashboard runtime suites passing on Chromium, Firefox, and WebKit.

## Upgrade Notes

- **Automatic cache rebuild on first run (`records-v8.json`, schema v23):** the record cache filename is now `records-v8.json` with internal schema version `23` (adding reporting-timezone binding, five-part billing components, pre-routing Claude request model names, native Anthropic direct-request evidence, and recovered Gemini working directories). The first run after upgrading from `0.2.0` will automatically re-scan your local logs once to build the new cache; older cache files are left untouched and source logs are never modified.
- **Default source discovery (`--source auto`):** running `tokens` without `--source` now auto-discovers and enables all readable sources among Claude Code, Gemini CLI, Codex, OpenCode, and Antigravity. Pass explicit `--source <name>` flags if you want to restrict a report to specific tools.
- **Regenerate older offline HTML snapshots:** offline dashboard HTML files generated with `0.2.0` do not contain the five-part billing components or new insight fields; re-run `./run dashboard` (or `tokens dashboard`) under `0.3.0` to use the Cost Ledger, Monthly Budget, Today's pace, and itemized `Other` views.
- **Restart running `tokens serve` processes:** a background `tokens serve` process started from an older checkout will not automatically reload updated code, cache schemas, or `PATH` changes (such as `zstd`); stop and restart the service after upgrading.
- **Browser-scoped local settings:** language preference (`tk-lang`), Today HUD position (`tk-hud-v1`), monthly budgets (`tk-budget-v1`), and custom unit prices (`tk-cost-v1`) are stored in the browser's `localStorage` per origin (`127.0.0.1:PORT` vs. `file://`) and are never uploaded or embedded into shared HTML reports.
