LIVE LOCALLY · OFFLINE WHEN EXPORTED

Explore usage without sending it away

tokens serve updates through a loopback-only local service. tokens dashboard exports the same interface as a self-contained offline HTML file.

Try before installingOpen the full interactive synthetic Dashboard. It runs entirely in your browser with generated sample data and reads no logs from your device.

Open the live dashboard

tokens serve --open

tokens serve \
  --source claude \
  --source gemini \
  --source codex \
  --source opencode \
  --source antigravity

tokens serve --anonymize --since 2026-08-01

The server binds only to 127.0.0.1; a single background worker scans log signatures on a 300-second default cycle. The homepage and API serve the latest successful in-memory snapshot directly and never wait for the next scan. The browser checks publish status at most every 60 seconds by default, and every 1 second while a prepare or scan is running; the page's 1, 5, 15, or 30-minute (or pause) choice only changes that browser polling, not the background scan. Initial preparation shows no placeholder zero, and later scan failures keep the previous statistics while showing the last successful check time. Unchanged signatures skip re-parsing. Conditional requests return 304 only when the published response version is unchanged and there is no scan error; a completed check can advance that version without changing the statistical snapshot. When report data changes, the worker reuses the parsed-file cache and publishes a new snapshot, and the page updates without a full reload.

Export an offline snapshot

tokens dashboard --open

tokens dashboard --anonymize --since 2026-08-01

The regular and pseudonymized exports use separate filenames (out/dashboard.html and out/dashboard-anonymized.html) and never overwrite one another. Exported HTML is a generation-time snapshot and does not watch for later log changes.

Today's brief

The top of the dashboard opens with BRIEF · TODAY, a deterministic rule-based summary (no model calls) built from your local records and read-only git outcomes:

One-line summary & status

Summarizes what today's reference-priced spend bought (commits and added lines, or the last 7 days' commits plus 7–14 day settled surviving lines when today has no commits yet), highlights the highest-retention project, the costliest no-commit session, the best-value model when at least two non-low-sample models exist, and flags spend above 2× the 7-day average or a new daily record. When outcomes are partial or unavailable, a status strip explains why in plain text.

Four brief cards

Retained lines per $1 · all range (surviving lines ÷ session spend, with the 7–14 day settled window trend when available), Rework tax (rolled-back share of settled added lines weighted by session spend), Subscription payback (month-to-date priced estimate ÷ a monthly USD fee stored only in local browser storage under tk-sub-v1), and Cache hit · Read (cache-read share of current tokens, naming the weakest source; not confirmed monetary savings).

Watch & savings tips

Shows up to three concise tips: an imminent quota alert when a Codex or Claude window is projected to hit its limit within two hours before reset, a costly in-repo session without commits, a source whose cache hit rate is below 25%, or an overall view cache-read share under 35%.

Core analysis

Day, week, and month

Switch granularity while trends, KPIs, model mix, project and session tables, and relevant details stay synchronized. An in-page language switch toggles English and Chinese in one pass (remembered locally in tk-lang), formatting numbers with K/M/B and English month labels in English mode.

Visible model filters

Standard checkbox chips support select all, clear, and one-step undo. No hidden double-click, right-click, or modifier gesture is required.

Period probe and comparison

Open a period to recompute its local view. Hold C for a temporary previous-period outline, or explicitly pin the comparison.

Projects and sessions

Where logs expose identifiers, inspect project trends and retained per-turn token sequences. A session keeps at most the most recent 200 turns. The Top projects and sessions block starts collapsed; jumping to Top from the section dock expands it.

Context composition

Fresh Input, Output, Cache Read, Cache Write, and Other reconcile to each source total. Cache Read is not presented as confirmed monetary savings.

Signal Dock and Exactness

Preview compatible views from a model, period, project, or session. Hold Alt/Option to expose exact values and semantic denominators.

Two-window comparison (A/B)

Use the ⇄ compare two windows control to select interval A, then a following, equal-length interval B. Change Attribution then decomposes the A → B difference by model. Only consecutive complete periods qualify; select bars by click, drag, or focus plus Enter. Clearing the selection returns the card to a single-period comparison.

Peak profile

Open the highest complete period to read its profile: period total, previous-period delta when a full neighbour exists, model mix, the busiest recorded hour, and retained project evidence. It shows recorded aggregates only and does not assert an anomaly or fault.

Itemized Other & per-source model slots

Up to eight top models keep distinct colors—with at least one slot guaranteed per active source—and Other uses neutral gray. In Model mix legends, trend legends, donut slices, trend tooltips, and a "More models" filter, folded models are itemized individually with their source, exact token count, and share. In the period breakdown table, clicking Other (N) expands folded models into individual columns (also itemized in CSV/Markdown exports). The Today HUD top model always shows a real model name.

Local cost ledger & monthly budget

Estimates costs from independent billing components using built-in USD official reference prices (GLM and Gemini rechecked 2026-11-19 alongside OpenAI, Anthropic, DeepSeek, and Moonshot; unpublished components stay blank instead of being guessed) or browser-saved manual overrides (tk-cost-v1), plus optional local monthly budget tracking (tk-budget-v1). Estimates are non-binding reference numbers, never actual billing charges.

Recorded backend and caliber

The snapshot header names the latest recorded backend in range, folding uncommon names into “Other”. Caliber notes spell out what figures are not: six hourly buckets are not a billing window, cache-read share is not a currency-savings estimate, and the coverage denominator is the all-model total at the current granularity. Logged model names are kept as recorded.

Overview insights & readable deltas

Three local views computed by insight_core.js: a today-vs-yesterday pace race at the same clock time (with a 7-day same-time average and yesterday-shaped full-day projection), a model share stream (7-day centered smoothing in share or stream mode) inside daily model usage, and an activity calendar. When the baseline (same time yesterday or the previous period) is zero or under 1% of the current value, the HUD, pace race, trend card, and copied summary say almost nothing at this time yesterday instead of noisy percentages; changes over +999% switch to multiples (such as 12.5×).

Model comparison (Best value)

The Model comparison · Best value card starts collapsed in the deep-dive area (expand state remembered locally in tk-dig-v1) and switches between By model and By tool views using the same read-only outcomes pipeline as tokens outcomes.

  • Columns: Name, Sessions, Spend, Commits, Added, Settled kept, Pending, Kept / $1, and Rework tax.
  • Proportional allocation: Spend is exact per model/tool. Commits, added lines, settled surviving lines, pending lines (under 7 days old), and rework tax are allocated by that row's share of the session's priced spend (falling back to token share only when priced spend is zero). One session can appear in several rows; manual commits outside every session are excluded.
  • Ranking and low-sample guard: Rows are ranked by settled retained lines per $1 (showing — when nothing is settled yet). Rows with fewer than 3 sessions or under $1 of settled spend carry a low sample badge and sit below the ranking.

Dark-first theme, glass shell, and Today HUD

Default dark & soft light

The dashboard defaults to dark, while light mode uses a calm warm light-gray surface (peak surface luminance around 85% of white, keeping WCAG AA contrast). Pass ?t=light, ?t=dark, or ?t=auto in the URL; view links omit t= unless overriding the dark default.

Glass shell with opaque fallback

Translucent blurred glass is reserved for the shell—the sticky section dock, popovers, command palette, toasts, and the Today HUD—while chart cards stay opaque. Environments with prefers-reduced-transparency or without backdrop-filter support fall back to opaque surfaces.

Today HUD

A collapsible, draggable floating widget showing today's tokens, calls, top model, same-time change vs. yesterday, and subscription quota burn-down rows. Drag to move, click or press Esc to collapse, and use arrow keys to nudge its position. It steps aside while overview KPIs are visible, moves to the bottom-left (starting collapsed) on narrow mobile screens, and persists only its position and collapsed state (tk-hud-v1).

Quota burn-down in Today HUD

When local Codex or Claude quota data is available, Today HUD shows one row per window using the same calculations as tokens quota: window name, source badge (official for Codex rate_limits snapshots; estimate for Claude 5h capacity estimated from historical no-limit safe windows and 429 limit hits, both using last-hour velocity), used percentage bar, reset time in the report timezone (reset …), and a projection note. tokens serve refreshes it on every snapshot; an offline export keeps the generation-time snapshot.

Data Trail

Press I to organize the current range into a non-modal evidence path:

  1. Confirm the selected range and model coverage.
  2. Choose a temporary model clue without silently changing the global filter.
  3. Choose one parallel branch: project, session, or context composition.
  4. Open the existing detailed module that supports the observation.
No invented relationshipProject and session evidence share a range and temporary model, but remain separate aggregates. The dashboard does not infer a project-to-session pairing from two independent relationships.

Optional labs

  • Data provenance: field coverage, freshness, skipped-file counts and reasons per source (distinguishing corrupt, partially corrupt, and empty files), replay-retention boundaries, and a copyable health summary.
  • Context Reuse River: time-based standardized token composition.
  • Activity rhythm: a 14-day by 24-hour weave, status pulse, and local rhythm profile.
  • Work Mode Atlas: explainable activity-pattern classification from local aggregates.
  • Token destinations: a two-column desktop view with a project and model overview on the left (from real project_model records) and wide session cards on the right, stacking vertically on mobile. Model buttons filter sessions locally with an All models reset; projects expose Signal Dock and Data Trail actions only and never infer project→session pairings. Sessions paginate 12 per page; the table view lists the full set with independent replay actions; SVG export captures the current page, filters, and theme.
  • Token Almanac: local snapshot history, personal records, and JSON export on the same device.
  • Achievements and share cards: local milestones, Passport, and Receipt views without global ranking claims.

Exact tables plus CSV and Markdown exports remain available alongside charts. Module preferences are stored locally. Labs can be hidden when the core report is enough.

Privacy boundary

The regular dashboard is sensitiveIt may embed complete working directories, session identifiers, derived titles, exact dates, and retained token sequences—not only the rows currently visible on screen.

--anonymize replaces project, session, and title identifiers with report-scoped aliases across the dashboard and its embedded outcomes block (and folds overflow models into Other so outcomes never leak folded model names). It still retains exact dates, kept models, values, aggregate relationships, and replay sequences, so it is pseudonymization rather than guaranteed anonymity.

Data Trail, Signal Dock, temporary exactness, and held comparison state stay in page memory. They do not add project or session IDs to URLs or localStorage. This browser-state boundary does not remove sensitive entities already embedded in a regular report.
