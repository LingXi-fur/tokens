概览模块数据流报告策略约束扩展入口
ARCHITECTURE

扁平、透明、纯 stdlib

项目以七个顶层 Python 模块组成一条短数据管线。命令行负责协调，读取器负责兼容，聚合层保持输出稳定，报告层各自渲染。

cli.py 位于协调层：解析参数、读取记录、选择日期窗口、调用聚合函数，再把结果交给终端、HTML 或 Dashboard 报告器。

模块职责

模块职责
config.py用户主目录、三类日志根、输出/缓存/摘要路径、Asia/Shanghai 时区、默认来源、模型别名。
readers.py解析 Claude / Gemini / Codex 日志，标准化记录；提供缓存、时间解析、会话标题与摘要加载能力。

report_html.py单期静态 HTML；Python 生成内联 SVG 柱图、饼图与明细。
report_dashboard.py构建扩展 payload，并把数据注入单文件 HTML 模板；浏览器端 vanilla JS 渲染交互 SVG。
cli.py命令入口、窗口计算、模式路由、文件打开。

数据流

1. 读取

readers.read_all() 按来源扫描日志。默认使用缓存；--no-cache 关闭缓存命中。未找到记录时，CLI 在报告生成前返回。

2. 窗口与筛选

compute_window() 为 day、week、month 计算默认起点和焦点日期。显式 --since 会覆盖默认起点，--until 默认当天。

3. 聚合

普通报告将过滤后的记录送入 by_day、by_week 或 by_month。Dashboard 直接拿记录，在 payload 中同时生成三种粒度及小时、项目、会话等扩展统计。启用 --anonymize 时，项目与会话 identity 会在写入任何 Top、flow 或 replay bucket 前转换为报告级 HMAC 别名，并跳过自然语言标题读取。

4. 渲染

终端报告直接打印；HTML 报告由 Python 拼装并写入；Dashboard 将 JSON 序列化后替换模板中的数据占位符。脱敏必须在这一序列化边界之前完成，因为 compact wire 只做压缩，不提供加密或隐私保护。

两种 HTML 报告策略

单期静态报告

Python 预计算所有 SVG 和表格。页面几乎不依赖 JavaScript，适合稳定归档与快速查看。

交互式 Dashboard

Python 生成 payload，浏览器端根据筛选状态重复渲染 KPI、SVG、表格与探索模块。项目透镜直接复用完整日级项目 → 模型聚合，不复制 record 级数据，也不推断项目 → 会话关系。所有代码仍在单文件内。

两者均无 CDN 与网络请求，主题主要依靠 CSS 变量和 prefers-color-scheme；Dashboard 另提供手动自动/亮/暗三态与 localStorage 记忆。

设计约束

  • stdlib-only：运行依赖保持为 Python 标准库；构建元数据只需要 setuptools。
  • 本地优先：日志读取、缓存和报告均在本机完成。
  • 文件输出：没有常驻服务和数据库；结果落在项目 out/。
  • 扁平模块：当前仍是顶层模块布局，pyproject.toml 通过 py-modules 明确列出。
  • 平台边界：自动打开实现使用 macOS open；其余核心 Python 逻辑面向 macOS / POSIX Linux。

扩展入口

增加新日志源通常需要：在 config.py 增加路径，在 readers.py 实现解析并输出统一字段，在 CLI 的 --source choices 中注册，再覆盖缓存与聚合测试。新增报告视图应尽量消费聚合输出，而不是重新解析原始日志。

保持边界展示层若需要 cwd、会话标识或自然语言摘要，应明确记录隐私影响，并在文档和分享流程中提醒，而不是假设“聚合”天然等于匿名。
