# tokens 0.3.0 发布说明

`tokens 0.3.0` 将本地优先的 AI 编程 Token 分析从三个工具扩展为五个自动发现的数据源——Claude Code、Gemini CLI、Codex、OpenCode 与 Antigravity——所有解析与报告生成依然完全保留在本机完成。交互式看板迎来默认暗色的视觉升级，新增今日浮窗（Today HUD）、同一时刻节奏对比与模型份额流洞察、内置官方参考价与本地月度预算的费用账本、透明拆分的 `Other` 模型明细，以及完整的中英双语界面。底层方面，冷启动扫描提速约 4 倍、本地缓存写入提速约 5 倍，新增 `tokens quota` 额度窗口分析、`tokens doctor --models` 路由归属诊断与 `tokens outcomes` 投入产出统计，并在 Windows、macOS、Linux 以及 Chromium、Firefox、WebKit 上全面通过跨平台验证。

## 新数据源（Antigravity 等）

- **新增第五个本地数据源 Antigravity：** 自动发现 `~/.gemini/antigravity/conversations/`（可通过 `TOKENS_ANTIGRAVITY_DIR` 覆盖），以只读方式读取各会话 SQLite 中的用量元数据（输入、输出、缓存读、模型、时间与会话），绝不打开对话正文或摘要数据库。
- **新增第四个本地数据源 OpenCode：** 以只读方式读取 `~/.local/share/opencode/opencode.db`（遵循 `XDG_DATA_HOME`），仅通过 SQL 提取 token、模型、时间、会话与目录字段（总量 = input + output + reasoning + cache read + cache write，其中 reasoning 记入 `thoughts` 思考分量），并自动跟踪 `-wal` 写入更新。
- **自动发现本机数据源（`--source auto`）：** 不传 `--source` 时默认检查全部五个已登记数据源的目录与读取权限，在不打开日志正文的前提下自动启用所有可读工具，并在终端报告、`tokens doctor`、`tokens quota` 与看板页头明确展示已启用和已跳过的来源。
- **模型归属与路由诊断（`tokens doctor --models`）：** 支持按日志中的请求名与解析后的归属模型分组统计 Claude 与 OpenCode 用量（可配合 `--since`、`--until`、`--json`），输出记录数、Token 总量、首末日期、归属依据（`logged`、`hex_alias`、`native_direct`、`router_rule`、`opencode_logged`）、当前 CCR 路由规则以及只读的 OpenCode 数据库健康计数，且绝不输出项目路径或会话 ID。

## 投入产出（tokens outcomes）

- **`tokens outcomes [--since] [--until] [--json]` 统计花费换来了什么：** 把每个会话的工作目录对应到 git 仓库（同一仓库的多个 worktree 合并计算），并把本人的提交（git config 身份，可用 `TOKENS_OUTCOME_EMAILS` 追加）按时间归到对应会话（从会话开始到最后活动后 30 分钟内）；merge 提交不统计，落在所有会话之外的提交计为手工提交，只给 `--since` 时范围到今天为止。
- **按天、项目、模型的留存与返工指标：** 统计新增/删除行数、7 天后仍在 HEAD 的留存行（只读 `git blame`，按仓库和提交缓存、HEAD 变化后失效）、返工税（会话新增行在 7 天内被删掉的比例乘以会话花费）、每 $1 留存行（另有仅满 7 天口径）与每提交成本；不满 7 天的提交保持待定（新增行照常统计，留存未知而非 0）；金额使用官方 USD 参考价，只覆盖可估价部分。
- **诚实的降级与单独分类：** 不在 git 仓库的会话（连同花费）与无提交会话单独列出；区块给出 `ok`、`partial`（仓库不可读、blame 超时、或单次构建 400 个提交的 blame 预算用尽——`reasons` 标明失败的检查，另含 `bad_session_ts`、`blame_cache_reset`、`no_repo`、`binary_commit`、`unestimated_cost`）或 `unavailable`（缺少 git，此时仍报告会话花费）。
- **隐私口径不变：** outcomes 块只含计数、比率和标签——不含提交信息、文件名或作者邮箱——项目名遵循 `--anonymize`；锁文件、`dist/`、`node_modules/`、`*.min.js` 不计入测量。

## 看板新功能

- **默认暗色主题与今日浮窗（Today HUD）：** 默认采用暗色画布并提供柔和暖灰亮色主题，半透明毛玻璃仅用于吸顶导航与浮层外壳；新增可折叠、可拖动的今日浮窗，实时展示今日 Token、调用次数、主力模型及与昨日同一时刻的对比变化。
- **总览与每日洞察：** 新增按生成时刻对齐的“今日 vs 昨日 · 同一时刻”节奏赛跑（含近 7 日同时刻均值与按昨日曲线外推的全天预估）、7 日居中平滑的模型份额流（支持“份额”与“河流”两种视图），以及跨周活动日历。
- **费用账本与月度预算：** 内置对照 Google Gemini、OpenAI、Anthropic、DeepSeek、Z.ai 与 Moonshot 官网核对的 USD 官方参考单价（GLM 与 Gemini 已于 2026-11-19 按官方页复核——GLM-5.3、5.3-Flash、5.3-FlashX、5.2、5.1、5 采用 Z.ai 国际美元价，含日志中出现的 `zhipu/` 写法，缓存存储限时免费期间缓存写记为 0，Gemini 4 Neon、4 Hydrogen、2.5 Pro、2.5 Flash、3 Flash Preview 采用 Google 标准付费档，官网未列出的型号保持未定价），支持按“来源 + 模型”手填覆盖单价、单模型恢复官方参考价、带已闭合自然日节奏外推的本地月度预算管理，以及基于精确十进制整数管线的费用 CSV 导出。
- **透明拆分的 `Other` 与 8 个独立模型色槽：** `Other` 改用中性灰并腾出第 8 个独立分类色（每个有用量的活跃来源至少保底占 1 个颜色槽位）；被折叠进 `Other` 的模型在模型构成图例、环形图切片、趋势悬停提示、可展开的明细表列（`Other (N)`）、导出文件与“更多模型”筛选器中均逐个列出名称、来源与精确用量。
- **报告时区日期范围栏与每日模型日期浏览：** 支持在报告时区下按“全部报告、今天、昨天、近 7 天、指定日”筛选核心视图，并在每日模型用量区提供连续 7 日快捷条、按需展开的月份日历选择器、每日模型明细表、请求名到后端名的“路由星图”SVG 流向图以及每日模型 CSV 导出。
- **等长 A/B 时段对比、峰值剖面与视图摘要复制：** 支持在趋势图上选择两个连续等长时段进行归因对比并展开已记录项目证据面板，主力模型易主时在总览卡亮出 `主力换人 X → Y` 徽章，支持一键展开峰值期剖面，并可在“当前视图”弹层中一键复制文字摘要。
- **重构“用量去向”（Token destinations）：** 将项目/模型概览与可读的会话卡片（每页 12 条）并排呈现，提供完整会话表格视图、每行独立的会话逐轮回放入口，以及标明当前分页、范围、模型筛选与主题的 SVG 导出。

## 英文界面

- **命令行与页面内语言切换：** 新增 `--lang en|zh` 控制终端报告与静态 HTML 语言（默认跟随系统 locale 或 `TOKENS_LANG`），交互式看板提供 `#lang-btn` 页面内即时切换按钮，且 Markdown 导出自动跟随当前看板语言。
- **切换语言一次性全量重渲染：** 点击语言按钮切换中英文时，日期范围栏、今日节奏、趋势图峰值与累计里程碑悬停提示、模型份额流、SVG 文字标签、已渲染的懒加载区块、已打开的弹窗及实时模式界面会一次性全部重新渲染，无需刷新页面。
- **英文数字单位与日期输入统一：** 英文界面下所有大数缩写统一使用 `K`/`M`/`B` 及英文月份与粒度名称（不再残留“亿/万”或中文月份），指定日输入改为带日历按钮的 `YYYY-MM-DD` 文本框，避免英文界面下出现浏览器自带的“年/月/日”占位符。
- **数据体检与能力徽章完整翻译并保护用户数据：** 直接以英文加载或切换至英文时，数据健康新鲜度说明、部分可用/不可用能力徽章（`◐`/`○`）、年鉴赛季名与工作模式说明均完整翻译为英文；同时项目路径、会话标题、提示词原文与模型名等用户数据保持原样不翻译。

## 性能

- **Claude 冷启动扫描提速约 4 倍：** 在 JSON 解码前直接快速跳过不含 `"usage"` 键的日志行，对 ≤ 256 KB 的常规用量行使用 C 实现的 JSON 解码器，对超长行继续保持有界流式解析。
- **本地记录缓存写入提速约 5 倍：** 改用 C 实现的 JSON 编码器逐条编码顶层缓存条目并流式写盘，内存占用仍严格限制在单条目内；真实 117 MB、20.2 万条记录的缓存写盘耗时从约 3.5 秒降至 0.64 秒。
- **非阻塞实时看板服务（`tokens serve`）：** 日志扫描在独立后台工作线程中运行（默认每 5 分钟一次），浏览器优先轮询轻量 `/api/status` 接口、仅在快照更新时拉取 `/api/snapshot`，并支持在本地缓存目录保存最近一次成功快照（`live-snapshot/last.json`）以实现重启后秒开展示与后台重验。
- **上调大历史日志采集与缓存上限：** 将整轮保留数据上限提升至 1 GiB、总记录数提升至 1,000,000 条、记录缓存文件上限提升至 512 MiB，并支持在有界内存下安全读取超过 64 MiB 的 Claude JSONL 文件与超过 4 MiB 的超长物理行。

## 正确性修复

- **订阅额度窗口查询（`tokens quota`）：** 读取 Codex 官方 `rate_limits` 快照（严格按 `window_minutes` 区分 5 小时与每周窗口），给出已用百分比、重置时间、近期消耗速度与预计撞线时刻；同时基于 Anthropic 直连记录与撞线事件提供明确标注为估算的 Claude 5 小时窗口容量（自动排除经 CCR 路由的第三方后端流量）。
- **准确区分 Claude 直连与 CCR 路由归属：** 携带 Anthropic 原生请求与消息证据（`req_*` 与 24 位 base62 `msg_` ID）的直连记录保留原模型名并归一化版本号（`native_direct`），不再被当前 CCR 路由规则追溯改写为路由后端；同时 CCR 十六进制别名（`anthropic/claude-ccr-h…`）可确定性解码并与目标后端身份合并。
- **全数据源严格拦截非有限 Token 数值：** 在 Claude、Codex、Gemini、OpenCode 与 Antigravity 全部五个来源中，凡出现 `NaN`、`Infinity`、负数、小数或布尔值的 Token 字段均不再进入任何合计（整条记录 Token 记为 0 且计费状态标为不确定，OpenCode 不再静默丢弃此类记录）。
- **跳过文件可见且自动重试：** 当 Gemini、OpenCode 或 Antigravity 的单个文件读取或解析失败时，数据健康区会按来源显示跳过的文件数与原因（读取失败或解析失败），且失败结果不写入缓存、下次运行自动重试；即使所选来源唯一的文件被跳过，看板仍会生成并说明缺口；Claude 与 Codex 遇到不完整读取时仍安全中止且不覆盖已有有效缓存。
- **区分损坏、部分损坏和空文件：** 数据体检把完全无法解析的文件和只有部分记录解析失败的文件分开显示（并给出忽略的记录条数），空文件不再报为失败。
- **环比归因与报告时区缓存口径一致：** 在启用日期范围且当前周期完整时，模型变化归因与主力换人徽章统一使用完整的上一周期（修复 2 月对比 1 月时漏算 29–31 日的问题）；记录缓存将解析后的日历日绑定到报告时区，切换时区时自动重新解析。
- **统一加固 CSV 导出转义：** 趋势表、每日模型表与费用账本 CSV 导出共用同一套单元格转义规则，对引号、逗号、换行以及公式注入前缀（`=`、`+`、`-`、`@`，含前导空白或控制字符后的前缀）进行安全转义。

## 跨平台（Windows / Firefox）

- **Windows Python 3.12+ 安全读取稳定性：** 修复 Windows 下读取未变化日志时因 `fstat`（修改时间）与 `stat`/`lstat`（创建时间）语义差异而误报 `Collection incomplete (file_changed)` 的问题，在支持创建时间（birth time）的平台上跨 API 比较创建时间，同时在 macOS 与 Linux 上保持完整 `ctime` 校验。
- **Windows Codex `.jsonl.zst` 流式解压：** Windows 下改用独立写线程向 `zstd` 子进程流式喂入压缩归档，不再依赖仅限 POSIX 的管道非阻塞标记或仅支持 socket 的 `selectors`。
- **Windows 缓存权限与时区支持：** 设置缓存文件描述符权限前安全检查 `os.fchmod` 可用性，并在 Windows 平台声明 `tzdata` 依赖以保证 IANA `--timezone` 在三大操作系统上行为一致。
- **Firefox 看板导航与跨浏览器一致性：** 费用账本卡片改为在页面初始加载时即完成渲染，且从导航栏或变化归因跳转区块前会预先渲染目标上方的懒加载卡片，消除滚动后的页面跳动；跨浏览器运行时测试在 Chromium、Firefox 与 WebKit 上全部通过。

## 升级注意事项

- **首次运行将自动重建记录缓存（`records-v8.json`，内部版本 v22）：** 记录缓存文件名已由 `0.2.0` 的 `records-v4.json` 升级为 `records-v8.json`，内部 schema 版本升至 `22`（新增报告时区绑定、五分量计费明细、Claude 路由前原始请求名及直连归属证据）。从 `0.2.0` 升级后首次运行时会自动重新扫描本地日志并生成新缓存，耗时较平时略长；旧缓存文件保留不删，原始日志始终只读不改。
- **默认自动发现所有可读数据源（`--source auto`）：** 不传 `--source` 时不再只扫描单一默认来源，而是自动发现并启用本机所有存在且可读的已登记来源（Claude Code、Gemini CLI、Codex、OpenCode、Antigravity）。如需仅统计特定工具，请显式传入 `--source <name>`。
- **旧版离线 HTML 快照需重新生成：** 使用 `0.2.0` 生成的旧离线 HTML 快照不包含五分量计费数据与新洞察字段；升级到 `0.3.0` 后请重新运行 `./run dashboard`（或 `tokens dashboard`）生成快照，方可使用费用账本、月度预算、今日节奏与拆分后的 `Other` 明细。
- **重启已运行的 `tokens serve` 常驻服务：** 从旧版本启动的后台 `tokens serve` 进程不会自动热加载新代码、新缓存格式或环境变量变更（如 `zstd` 路径）；升级后请手动停止并重启服务。
- **浏览器本地存储按源隔离：** 语言偏好（`tk-lang`）、今日浮窗位置（`tk-hud-v1`）、月度预算（`tk-budget-v1`）与自定义模型单价（`tk-cost-v1`）仅保存在当前浏览器的 `localStorage` 中（按 `127.0.0.1:PORT` 或 `file://` 作用域隔离），不会上传或嵌入到导出的分享报告中。
