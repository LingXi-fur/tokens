COMMAND LINE REFERENCE

一个入口，覆盖用量、额度与投入产出

源码检出使用 ./run；完成本地 editable 安装或安装发布版 wheel 后使用 tokens。在原有九种命令模式基础上新增 outcomes，共十种模式。

语法

./run [day|week|month|all|dashboard|demo|serve|doctor|quota|outcomes] [options]  # 源码检出
tokens [day|week|month|all|dashboard|demo|serve|doctor|quota|outcomes] [options]  # 本地 editable 安装或 wheel 后

统计模式

模式默认窗口聚合方式
day最近 14 天按日；默认模式，焦点为今天
week最近 8 周按周
month最近 6 个月按月
all全部历史按日
dashboard筛选后的全部记录导出可离线打开的日 / 周 / 月快照
demo生成的 91 天样本只生成合成 Dashboard，不读取本机 AI CLI 日志
serve筛选后的全部记录启动仅绑定本机回环地址的实时 Dashboard
doctor不读取记录内容检查来源、候选文件、时区、输出和缓存目录；加 --models 可查看 Claude 与 OpenCode 模型归属报告
quota当前 5 小时 / 周窗口订阅额度快照与预计撞线时间（Codex 官方快照、Claude 估算、OpenCode 无官方数据）
outcomes记录自身的日期跨度只读统计 git 投入产出：按天、项目、模型与工具输出会话花费、提交、7 天留存行、返工税、每 $1 留存行与每提交成本

订阅额度（quota）

tokens quota 用于查看当前订阅窗口剩余额度与按当前速度推算的撞线时间。支持 --json 输出机器可读格式、--source 限定来源，以及 --no-cache 绕过本地 quota-v1.json 扫描缓存。

  • Codex 与 Claude 的区别：Codex 读取本地会话日志里的官方 rate_limits 快照（按 window_minutes 区分 5 小时窗口与周窗口），展示真实已用百分比、重置时间与近 60 分钟速度；已重置的窗口会标记为已重置，不展示过期百分比。Claude 没有官方百分比，因此明确标注为估算：容量来自 429 撞线窗口内的 Anthropic 直连 token 中位数（hits），或已完成未撞线窗口的最高用量下限（safe_floor）；经 CCR 路由到其他后端的 token 不计入 Anthropic 额度。OpenCode 报告无官方额度数据。
  • 五种状态含义：hit（按当前速度预计在重置前撞线，或已撞线）、safe（预计撞线时间晚于重置，本窗口安全）、past_floor（按当前速度将超过历史最高未撞线用量 safe_floor，不代表一定会撞线）、beyond_estimate（当前用量已超过历史估算仍未撞线，说明估算偏低），以及 insufficient（窗口刚开始、快照不足两个或时间跨度太短，数据不足）。
  • 首次运行耗时说明：首次运行需要扫描全部本地日志，可能耗时几分钟；之后会复用 quota-v1.json 与读取器缓存，通常只需十几秒。
  • 隐私边界：只读取本地额度相关元数据字段（时间戳、额度字段、模型名与 token 合计），不联网、不读取消息正文，输出也不含 cwd、会话 ID 或项目名。

投入产出（outcomes）

与 quota 回答“额度还剩多少”不同，tokens outcomes 回答的是“花费换来了什么”。它把每个会话的工作目录对应到本机 git 仓库（同一仓库的多个 worktree 自动合并计算；工作目录已被删除的 OpenCode 会话和在 ~/.gemini/projects.json 登记的 Gemini 会话也能找回对应仓库），把本人的非 merge 提交（身份取自 git config user.email / user.name，可用逗号分隔的 TOKENS_OUTCOME_EMAILS 追加）归到对应会话（从会话开始到最后活动后 30 分钟内），并复用费用账本的官方 USD 参考价核算花费。

  • 每 $1 留存行（保留行数 / $1）：以 留存行（提交满 7 天后通过只读 git blame 测得仍在当前 HEAD 的新增行，结果按仓库和提交缓存在 outcomes-blame-v1.json，HEAD 变化后失效）除以花费。终端同时给出全范围口径（每 $1 留存行）和仅满 7 天口径（每 $1 留存行（仅满 7 天），即留存行 ÷ 已定案花费）。缺少官方参考价的记录贡献 token 但不计金额，报告会注明金额只覆盖可估价部分。
  • 7 天观察期（待定行）：不满 7 天的提交处于观察期——其新增行照常统计在 待定 列，但留存明确报告为未知（—），绝不记成 0。若范围内所有新增行都不满 7 天，终端显示 —（所有新增行都不满 7 天，留存待定）。
  • 返工花费（返工税）：对已满 7 天的会话，按 7 天内被删掉的新增行占比乘以该会话花费（cost × max(0, settled_added − surviving) / added）。
  • 每次提交成本（每提交成本）：总会话花费 ÷ 范围内总提交数。不在任何 git 仓库的会话（含无工作目录会话）与仓库内无提交会话分别单独列出；锁文件、package-lock.json、dist/、node_modules/ 与 *.min.js 不计入测量（可用分号分隔的 TOKENS_OUTCOME_EXCLUDE 追加排除模式）。
  • 按模型与按工具两张表，以及低样本 * 标记：按模型 与 按工具 两张表按 (工具, 模型) 桶精确拆分花费，绝不把整场多模型会话全算给“主力模型”；提交、新增行、已定案留存、待定行与返工税按该项在会话花费中的占比分摊（仅当会话内所有可估价金额都为 0 时改用 token 占比）；同一会话可出现在多行，落在所有会话之外的手工提交不计入这两张表。少于 3 个会话或已定案花费低于 $1 的行在名称后标 *（样本少），排在已排名行之后且不参与按 每 $1 留存行 的排名。
  • 日期范围、降级状态与 --json 输出：--since / --until（闭区间，按报告时区）限定范围——只传 --since 时统计到今天为止，只传 --until 时从最早记录日起，都不传则覆盖记录自身的日期跨度；另支持 --source、--lang zh|en 与 --no-cache。状态分为 ok（正常）、partial（仓库不可读 repo_unavailable、单文件 blame 超 10 秒 blame_timeout 或单次构建 400 个提交预算用尽 blame_skipped）以及 unavailable（缺少 git git_missing，此时仍报告会话花费）。传入 --json 输出机器可读 JSON，顶层包含 schema、range、status、reasons、totals、days、projects、models、sources、no_commit_sessions 与 no_repo_sessions。

参数

参数类型 / 默认说明
--sinceYYYY-MM-DD起始日期；提供后覆盖模式默认起点。
--untilYYYY-MM-DD / 今天结束日期。
--days正整数 / 14day 模式回看天数。
--weeks正整数 / 8week 模式回看周数。
--months正整数 / 6month 模式回看月数。
--source可重复选择 antigravity、claude、codex、gemini、opencode 或 auto；默认 auto（自动启用所有可读的已登记来源）。
--output DIR./out选择报告输出目录。
--timezone AREA/CITY系统本地时区使用 IANA 时区解释日期和小时。
--lang en|zh英文或中文终端及单期静态 HTML 报告语言；默认依次使用 TOKENS_LANG、系统语言。Dashboard 在页面内切换语言。
--html开关在终端报告之外生成单期静态 HTML。
--dashboard开关生成交互式 Dashboard；等价于位置模式 dashboard。
--anonymizeDashboard 开关在离线、合成 Demo 或实时 Dashboard 中以服务 / 报告生命周期内稳定的别名替换项目路径、会话标识和自然语言标题（同时作用于看板内嵌的投入产出区块）。
--modelsdoctor 开关与 doctor 联用，展示 Claude 请求名到模型的归属依据，并包含 OpenCode 只读数据库健康统计。
--json开关与 doctor --models、quota 或 outcomes 联用，输出机器可读的 JSON。
--interval SECONDS秒 / 300后台日志扫描周期，最小为 1。页面下拉的 1 / 5 / 15 / 30 分钟或暂停只改变浏览器轮询，不影响该后台扫描。
--port PORT端口 / 8765实时模式本机回环端口；传 0 由系统选择可用端口。
--open开关用系统默认浏览器打开生成文件或本机实时 URL。
--no-cache开关忽略文件缓存，强制重读日志。
--version开关输出当前版本。

示例

无需本地日志

tokens demo --open

终端报告、额度与投入产出

tokens
tokens week
tokens month --months 12 --lang zh
tokens all
tokens doctor --models --json
tokens quota --json
tokens outcomes --since 2026-10-01
tokens outcomes --since 2026-10-01 --until 2026-10-31 --json

多来源

tokens day --source claude --source gemini
tokens month --source codex
tokens day --source opencode
tokens day --source antigravity

精确日期范围

tokens day --since 2026-01-01 --until 2026-03-31
tokens dashboard --since 2026-01-01 --until 2026-12-31

Dashboard

tokens serve --open
tokens serve --port 0 --interval 2
tokens dashboard
tokens dashboard --anonymize
tokens --dashboard --open

行为说明

  • 不传 --source（默认 auto）时只检查路径存在性与权限，自动启用五个已登记来源（Claude Code、Gemini CLI、Codex、OpenCode、Antigravity）中可读的来源；报告与 doctor 会显式列出检测与跳过的来源（doctor --models --json 与 quota --json 包含 sources_detected / sources_skipped）。
  • 默认使用系统本地时区；可用 --timezone Asia/Shanghai 等 IANA 名称显式覆盖。
  • 如果没有读到记录，命令返回状态码 1，并提示运行 tokens doctor（Dashboard 模式下若 Gemini、OpenCode 或 Antigravity 存在单文件跳过，仍会生成看板并在数据体检中说明缺口）。
  • 普通模式始终先输出终端报告；只有指定 --html 才额外写文件。
  • 离线 Dashboard 保留日期与来源筛选，并在生成文件内提供日 / 周 / 月切换。
  • 实时模式只绑定 127.0.0.1，单个后台 worker 按默认 300 秒周期扫描文件修改时间与大小签名（Windows 另检查句柄变更时间）；页面下拉的 1、5、15、30 分钟或暂停只改变浏览器轮询，不改变后台扫描。签名未变化时不重新解析；只有已发布响应版本未变化且没有扫描错误时，条件请求才返回 304。成功检查可以推进响应版本，而不改变统计快照。
  • 首页与 API 直接读取最近一次成功的内存快照，不等待下一次扫描；初始准备不展示占位 0，后续扫描失败时保留旧统计并显示上次成功检查时间。
  • 实时模式可以在初始没有记录时继续等待；按 Ctrl+C 停止。
  • --anonymize 仅接受 dashboard、demo 或 serve 模式；它保留精确日期、Token、模型、匿名关系与匿名会话回放，因此是假名化而不是完全匿名。
  • 报告默认写入当前工作目录下的 out/；记录缓存（records-v8.json）、额度扫描缓存（quota-v1.json）、留存行缓存（outcomes-blame-v1.json）和实时快照缓存（live-snapshot/last.json）写入平台用户缓存目录，与报告分离。
不要把 --open 当成生成条件它只控制生成后是否自动打开。自动化与回归测试中建议省略，避免启动 GUI。
